# 把闲置 Kindle 改成墨水屏看板 —— 完整工程记录

> 一台 2015 年的 Kindle Paperwhite 3，一块 300ppi 的墨水屏，
> 一个云服务器上跑的渲染服务。从越狱到最终跑通，前后折腾了几天，
> 踩了二十多个坑。这份文档是完整记录。
>
> **本文已脱敏**：去掉了服务器地址、域名、部署路径等环境信息，只保留技术内容，可直接发布。
>
> 技术细节（尤其是每个坑的完整分析）另见 [`pitfalls.md`](pitfalls.md)，
> 本文是**总纲 + 关键决策 + 索引**。

---

## 0. 项目概览

### 目标

把闲置的 KPW3 变成一块常显信息面板，显示：

- 日期、星期、当前时间
- 天气（当前 + 未来 5 天）
- **MiniMax Token Plan 额度**（两个滚动窗口的剩余百分比）
- 电量
- 顺带：设备本地时间（离线时用来判断数据是否过期）

### 架构

```
┌─────────────────────┐   HTTP GET      ┌──────────────────────┐
│  Linux 服务器        │ ──────────────▶ │  KPW3（已越狱）       │
│  Python + Flask     │  dashboard.png  │  eips 刷屏            │
│  Pillow 渲染 PNG    │ ◀── ?batt=85    │  RTC 唤醒 → 休眠      │
│  拉天气 + 查额度     │                 │  只拉图，不渲染        │
└─────────────────────┘                 └──────────────────────┘
```

**核心设计：渲染全部放在服务端，设备端只做三件事 —— 拉图、刷屏、睡觉。**

这个决定贯穿了整个项目，也是它能跑起来的关键（原因见第 1 节）。

### 最终状态

| 项 | 值 |
|---|---|
| 设备 | Kindle Paperwhite 3（第七代，2015） |
| 固件 | 5.16.2.1.1（官方最终版，已停更） |
| 越狱 | LanguageBreak |
| 服务器 | 云服务器 CentOS 7.9，Python 3.9（Miniconda） |
| 服务端 | Flask + Pillow，systemd 常驻 |
| 刷新间隔 | 600 秒（电池）/ 300 秒（插电） |
| 一次充电 | 数周级别 |

## 1. 为什么选这个架构

### 考虑过的三条路

| 方案 | 做法 | 为什么没选 |
|---|---|---|
| **设备端渲染** | Kindle 上跑绘图程序，直接画屏 | Kindle 的 root shell 里**没有可用的绘图库**（没有 PIL、没有 ImageMagick），画个中文字都费劲 |
| **服务端渲染** ✅ | 服务器画好 PNG，设备拉图贴屏 | **选了这条** |
| **用现成产品** | 买个 TRMNL 之类的墨水屏看板 | 手上有闲置 Kindle，折腾本身就是目的 |

### 服务端渲染的三个好处

1. **调试快几十倍** —— 调布局在浏览器里刷新就行，不用一遍遍刷墨水屏（墨水屏全刷一次要 1-2 秒，而且费屏）
2. **设备端极简** —— Kindle 只需要 `wget` + `eips` 两个命令，对老设备友好
3. **能力不受限** —— 服务器上想画什么画什么（中文字体、渐变、图表），设备端完全不用管

### 代价

**离线就废了。** 拉不到图，屏幕一直显示最后一次成功的那张。

这个代价一开始没意识到，后来才发现它引出了一连串问题（见第 6 节）。

## 2. 硬件与固件：先把参数搞对

### KPW3 的屏幕

| 参数 | 值 |
|---|---|
| 分辨率 | **1448 × 1072** |
| PPI | 300 |
| 灰度 | 16 级 |

**⚠️ 网上大量教程写的 `758×1024` 是 Paperwhite 1/2 代的**，照抄到 KPW3 上画面会错位。

### ★★ framebuffer 是竖屏的（这是第一个大坑）

实测 `eips -i`：

```
xres: 1072    yres: 1448    bits_per_pixel: 8    grayscale: 1    rotate: 3
```

**显存本身是 1072×1448 的竖屏布局**，而 `eips -g`（贴图）**不做任何旋转、也不转色深**（官方 wiki 上它的全部选项只有 `-g -b -w -f -x -y -v`）。

所以服务端必须自己把图转好再传：

```python
img.transpose(2)      # 1448×1072 → 1072×1448（逆时针；2 == ROTATE_90）
img.convert("L")      # 8 位灰度，跟 framebuffer 对齐
```

**漏了会怎样**：图片右边被切、内容错位，**而且会惊动 `framework` 弹出软键盘把画面盖住**（因为触碰到了它的领地）。

> 用 `transpose(2)` 而不是 `Image.Transpose.ROTATE_90`，是因为后者要 Pillow ≥ 9.1，
> 而依赖下限写的是 8.0 —— 否则服务启动即崩。

## 3. 越狱

**流程要点**（完整分步见 [`jailbreak.md`](jailbreak.md)）：

1. 固件 ≤ 5.16.2.1.1，开飞行模式，关密码
2. 用 **LanguageBreak**（KPW3 上别用 WinterBreak，有重启报错的反馈）
3. 装 hotfix —— 要用 **KindleModding 通用版（2.5.0）**，不是 LanguageBreak 自带的
4. 装 MRPI（选 FOR MODERN DEVICES）+ KUAL + USBNet

### 越狱后立刻要做的一件事

**联网前先在 KUAL 里执行 `Rename OTA Binaries`。**

否则亚马逊推一个官方固件过来，越狱就没了。**越狱成功 ≠ 阻止升级。**

### 一个认知修正

**越狱 ≠ 安卓。** 拿到的只是一个 root shell —— **装不了 apk**，跑不了安卓应用。所以"在 Kindle 上跑 Obsidian"这种想法直接出局（只能用 KOReader 读 md）。

## 4. 服务端

### 技术栈

```
Flask（HTTP 服务） + Pillow（渲染） + PyYAML（配置）
```

### 渲染流水线

```
拉数据（天气 / 额度）→ 在 1448×1072 横屏画布上排版
  → transpose(2) 转 90° 逆时针
  → convert("L") 转 8 位灰度
  → PNG 输出
```

**布局用 margin 留出安全边距**（`margin = 72`），所有内容都在边距内 —— 后来这个设计意外帮了大忙（见第 5.5 节，本地时间就写在边距里）。

### 数据源

| 源 | 说明 |
|---|---|
| **天气** | Open-Meteo，免费无 key |
| **额度** | MiniMax Token Plan 官方接口 |

### ★ MiniMax 的三个坑

**① 国内站和国际站凭证不互通**

```
国内：platform.minimaxi.com → api.minimaxi.com
国际：platform.minimax.io  → api.minimax.io
```

在哪个平台拿的 key 就必须打哪个域名，**跨区必定报 `2049 invalid api key`**。

**② key 类型看前缀**

- `sk-cp-` = Subscription Key（这个接口要的）
- `sk-api-` = pay-as-you-go 的 API Key（接口不认）

**③ 社区文档里的响应结构是错的**

实测真实结构：

```json
{
  "model_remains": [
    {
      "model_name": "general",
      "current_interval_remaining_percent": 100,   // ← 5 小时窗口剩余，用这个
      "end_time": 1790146800000,
      "current_weekly_remaining_percent": 99,      // ← 周窗口剩余
      "weekly_end_time": 1790524800000
    }
  ],
  "base_resp": { "status_code": 0 }
}
```

**没有 `data` 层**，额度按模型拆在 `model_remains[]` 里，而且 `total/usage_count` 恒为 0 —— **真正有效的只有 `remaining_percent`**。

> **教训：官方没给 schema 的时候，先写探测脚本，别照抄社区文档。**
> 这个坑花了最多时间，因为它不报错 —— 只是数值一直是 0。

### ★ 百分比口径：必须标明「剩余」还是「已用」

这个坑很隐蔽：MiniMax 返回的 `current_*_remaining_percent` **本来就是"剩余"**，代码却做了 `100 - x` 翻转 —— 结果**满额度被画成 0% 空条**，"还能用多少"被传达成"没额度了"。

**数据、接口、渲染全都正常，只有语义反了。**

**口径统一为「剩余」**：满额 = 满条。

### 部署

| 角色 | 监听 | 说明 |
|---|---|---|
| **nginx** | `0.0.0.0:8787` | 对公网，Kindle 访问的就是它 |
| **Flask** | `127.0.0.1:8789` | 仅本机，由 nginx 反代 |

**两边必须错开端口。** Flask 也去听 8787 会和 nginx 抢端口，报 `Address already in use`，而且 `pkill main.py` 杀不掉 —— **占用者其实是 nginx**，会让人排查到怀疑人生。

CentOS 7 的 SELinux 默认禁止 nginx 外连 → 502，需要：

```bash
setsebool -P httpd_can_network_connect 1
```

## 5. 设备端

### 5.1 刷新循环

```sh
while true; do
    hold_screen              # 压住原生界面
    wifi_on                  # 等网络就绪（见 5.4）
    check_quit_request       # 问服务端要不要退出
    fetch_image && draw_image  # 拉图 + 刷屏
    draw_clock               # 叠本地时间（见 5.5）
    setup_alarm              # 设 RTC 闹钟
    echo mem > /sys/power/state   # 深度休眠
done
```

**深度休眠是关键**：`echo mem` 让 CPU 断电，但**墨水屏画面保留**（不需要持续供电）。所以一次充电能撑很久。

### 5.2 ★ 屏幕接管：只停两个，保留 `framework`

```sh
initctl stop lab126_gui    # 主页/界面层
initctl stop webreader     # 浏览器组件
# ★ framework 不动
```

**为什么保留 framework**：电源键的**短按事件正是 framework 处理的**。停掉它，按键就全失灵，人被锁在画面里出不来。

**这里的取舍**（踩了两次才搞明白）：

| 停 framework | 好处 | 代价 |
|---|---|---|
| **停** | 屏幕上绝对不会有原生 UI 冒出来 | **所有按键失灵，无法重启** |
| **不停** ✅ | 短按电源键（休眠/唤醒）正常 | 触摸时可能弹软键盘 |

后者划算得多 —— 而且"可能弹键盘"对一块**放着看**的看板来说几乎不是问题。

### 5.3 ★ 退出路径：只剩「强制重启」一条

**结论：唯一可靠的办法是长按电源键 10 秒以上强制重启。**

#### 为什么只剩一条

**第一层原因：看板跑起来后，Kindle 上输入不了任何命令。**

搜索框由 `lab126_gui` 提供，而看板为了独占屏幕**正是把它停掉了**。
`;log` 命令的**执行**确实是系统级的（不依赖界面），但**输入 `;log xxx`
需要搜索框** —— 所以实际用不了。

> 我们一开始把"命令**执行**通道"和"命令**输入**方式混为一谈了：
> 前者确实是系统级的，但**没有输入，再好的通道也用不上**。

**第二层原因：网页遥控依赖网络，而看板的网络并不可靠。**

设备连的是手机热点，热点一关设备就离线 —— 此时它根本拉不到
"用户点了退出"这个状态。

> **实测记录**：热点关着时，在网页上点「退出看板」，再按电源键唤醒设备，
> **依然退不出来**。因为唤醒后 `check_quit_request` 的请求也失败了
> （日志：`本机未连接网络（1.1.1.1 不可达）`）。
>
> ⇒ **你越需要它工作的时候（断网、出问题），它越是用不了。**

#### 所以就一个办法

| 操作 | 说明 |
|---|---|
| **长按电源键 10 秒以上，直到重启** | 不需要网络，永远可用 |

**关键细节**：

- **看板运行时，长按电源键弹不出「重启 / 取消 / 熄屏」菜单**
  （suspend 状态下长按的语义是"唤醒"），**但按得够久仍会强制重启**
- 想要那个菜单，得在**看板没跑的时候**长按
- `stopdash.sh` / `;log stopdash` 的定位是「**看板已停之后**清理残留、
  恢复原生界面」，**不是退出运行中看板的手段**
- 网页遥控的代码保留着（网络正常时理论上可用），
  但**不能把它当退出方案**
- **退出后必须 ack 复位服务端状态**，否则下次启动一问又是 `quit=true`
  → 立刻又退出去，表现是"看板再也起不来"
- **写操作必须鉴权**：`/dashboard.png` 只读无所谓，`/control/quit` 是写操作，
  接口敞开等于任何人都能远程关掉你的看板

### 5.4 ★ 网络：等待 + 自愈

设备连的是**手机热点**，所以断网是常态而非异常。

**① 网络等待（替代固定 `sleep`）**

```sh
wait_for_wifi() {
    while [ "$_i" -lt "$WIFI_WAIT_MAX" ]; do
        ping $PING_OPTS "$WIFI_TEST_IP" >/dev/null 2>&1 && return 0
        _i=$((_i + 1)); sleep 1
    done
}
```

- 探的是 `1.1.1.1`（公共 IP），**不是自己的服务端** —— 这样能区分「本机没网」和「网通但服务端挂了」
- 内核报 `unreachable`（热点关了）时**立刻返回**，不空等满 30 秒
- **探测失败不阻断主任务** —— 返回值只用来分类记日志

**② WiFi 自愈**

连续 3 轮网络故障后，自动 toggle 无线（关 5 秒 → 开 5 秒）。

**为什么要这个**：实测发现**热点恢复后设备并不会自己重连** —— 观察到的现象是"必须插拔一次 USB 才恢复"。而 toggle 无线就是等效的"踢一脚"。

### 5.5 ★ 本地时间叠加

**为什么需要**：看板是**静态图**，离线时一直显示最后一次成功拉到的那张，图上的时间也是那一刻的。**光看图不容易发现"数据已经过期很久了"**。

于是在屏幕角落叠一行本地时间：

```sh
draw_clock() {
    "$EIPS" 0 59 "NOW $(date '+%m-%d %H:%M')"
}
```

**这样离线时**：图上的时间停住、`NOW` 继续走 —— **两者越差越远，就是数据过期的程度。**

**eips 写字的语法和坐标系（真机实测得出）**：

```
eips <列> <行> "文字"        ← 第一个参数是「列」(横向)，第二个是「行」(纵向)
```

- **字符格约 16×24 像素**（竖屏 1072×1448 ÷ 16×24 ≈ 67 列 × 60 行，正好对上）
- **行 60 画不出来** → 有效范围 0~59
- 位置选 `列 0 行 59`：对应横屏设计的 x ≈ 7~31，落在服务端的 72px 边距里，**不压任何内容**

**调用时机（有个坑）**：

- `draw_image` 是**全屏贴图**，会盖掉叠上去的字 → 必须**先贴图、后写字**
- **拉图失败时也要重写时间** —— 这才是有价值的部分（图不动，时间照走）

**已知限制**：`eips` 沿 framebuffer 横轴排字、**字符正立**，没有旋转参数。而看板是横着看的，所以这行字在视觉上**是竖排的、字母躺倒**。这是 `eips` 的能力边界，脚本层绕不过去。

### 5.6 免 SSH 入口：`;log runme`

USB RNDIS 网卡不出现、WiFi 22 端口不通 —— **SSH 通道走不通**。

替代方案：把脚本放 `/mnt/us/`，用**搜索框**触发：

```
;log runme      → 执行 /mnt/us/runme.sh
;log stopdash   → 执行 /mnt/us/stopdash.sh（仅看板未运行时可用）
```

**★ `;log` 只认固定的几个命令名**（白名单），换个新名字会直接报 `wrong args`。
所以**任何临时/调试功能都必须挂在 `runme` 这个入口下面**。

> ⚠️ 但注意：这套入口**只在看板没有运行时可用** —— 看板跑起来后
> 搜索框（`lab126_gui`）被停了，敲不出任何命令。

**脚本怎么进设备**：Windows 覆盖 Kindle FAT 分区上**已存在的文件会失败**（新建可以），所以惯例是"放新名字 + 手动 `mv` 覆盖"。

## 6. 电源管理：这个项目最深的一课

这一节单独拎出来，因为**这里的坑最反直觉，也最贵**。

### 6.1 深度休眠会"吃掉"长按电源键

**现象**（真机对照实验）：

| 状态 | 长按电源键 6 秒 |
|---|---|
| **不跑看板** | ✅ 正常弹菜单：重启 / 取消 / 熄屏 |
| **看板运行中** | ❌ 整屏闪一下 → **全黑**，没有菜单 |

**根因**：看板为了省电，每轮刷完图都 `echo mem` 进深度休眠，**大部分时间都在睡**。

> **设备一旦 suspend，powerd 对电源键的解释就变成「唤醒」，而不是「弹 UI 菜单」。**

所以按住 8 秒，系统实际做的是"被唤醒 → 跑一轮 → 又睡回去"。"闪一下 + 全黑"就是这个醒睡循环的痕迹。

**这是取舍，不是 bug**：续航（要睡）和弹菜单（要醒）在"设备是否 suspend"这一点上直接对立。**选了保休眠。**

**想重启 → 先退出看板，回原生界面再长按。**

### 6.2 自建电源键监听：走不通

一开始想"绕开 framework 自己读内核按键事件"，**在 KPW3 上彻底不可行**：

- 电源键设备名是 `max77696-onkey`
- 它的 `capabilities/key` 位图里**没有声明 KEY_POWER(116)**

**⇒ 这个按键事件在用户态根本看不见。**

按名字匹配（靠猜）和按能力位图匹配（靠内核声明）**两条路都堵死**。

> **教训：「设备支持某功能」≠「该功能对用户态可见」。**
> 规则匹配失败时，应该**写一次穷举诊断**把"这台机器到底能听到什么"说清，而不是继续加规则。

### 6.3 USB 掉盘

**现象**：看板运行时插 USB 到电脑，盘会掉、过会儿又回来。

**根因**：`echo mem` → 系统 suspend → **USB 连接随之断开** → 电脑掉盘；唤醒后重新枚举 → 盘回来。

**这是 suspend 的固有行为，设备侧无解。**

**补充发现**：Kindle 还有个**固件级怪癖**（有 Linux 内核补丁为证）——

> Kindle 在收到 `SYNCHRONIZE CACHE` 后约 **1 秒内**没收到下一个 SCSI 命令，就会**自动移除自己模拟的介质**，即使主机发了"禁止弹出"命令也没用。

修复在**主机侧**（内核 5.12+ 的 quirk），**Windows 上没有对应补丁**。

**实用结论**：**要拷文件，先退出看板再插线**（退出方式见 5.3 —— **长按电源键 10 秒重启**）。
这也是全项目的惯例。

| # | 坑 | 一句话教训 |
|---|---|---|
| 1 | MiniMax 跨区认证失败 | 国内/国际站**凭证不互通**，跨区必报 2049 |
| 2 | 响应结构和文档不符 | 官方没 schema 时，**先探测再写解析** |
| 3 | 额度百分比画反 | **字段口径必须标明「剩余」还是「已用」** |
| 4 | CentOS 7 CA 证书太老 | HTTPS 下载**静默失败**（下出 0 字节），要 `curl -k` |
| 5 | systemd 优先级高于 `.env` | 两处都设会以 systemd 为准，**二选一** |
| 6 | `status=1/FAILURE` | 先看 `journalctl` 完整日志，高频真因是**端口被占** |
| 7 | 域名加了端口也可能被拦 | 先 `curl -i` 看是不是 302 到拦截页 |
| 8 | Pillow 版本下限放太宽 | 依赖下限要和用到的 API 对齐（否则启动即崩） |
| 9 | 缓存键不完整 | **缓存键必须覆盖所有影响输出的输入**（如电量） |
| 10 | 深度休眠改变设备语义 | suspend 后按键语义、USB 连接**都会变** |

**还有几条属于"通用工程教训"**：

- **失败方向要选安全的那一侧** —— 解析不出来 / 请求失败 → 一律按"不做动作"处理
- **等外部条件用「轮询 + 超时」，不要用固定 `sleep`** —— 死等固定秒数隐含"耗时稳定"的假设，而网络/硬件初始化根本不成立
- **「诊断细粒度」≠「修复细粒度」** —— 诊断可以分得很细（省时间、记日志），但修复动作要偏向"宁可多踢一脚"（因为漏掉的代价更大）
- **对比实验比推理可靠** —— "不跑脚本 vs 跑脚本"这一个对照，直接锁定了变量

## 8. 速查表

### 设备端文件

| 路径 | 作用 |
|---|---|
| `/mnt/us/runme.sh` | 免 SSH 入口（`;log runme` 触发），负责启动/停止看板 |
| `/mnt/us/stopdash.sh` | 看板已停后清理残留、恢复原生界面（**不能退出运行中的看板**） |
| `/mnt/us/dashboard/dashboard.sh` | 刷新守护主脚本 |
| `/mnt/us/dashboard/config.env` | 配置（token 等），**填一次永久生效** |
| `/mnt/us/dashboard/dashboard.log` | 运行日志 |
| `/mnt/us/dashboard/dashboard.png` | 当前显示的那张图 |

### 常用操作

| 想做什么 | 怎么做 |
|---|---|
| 启动看板 | 搜索框 `;log runme` |
| 退出看板 | **长按电源键 10 秒以上强制重启**（唯一可靠方式，见 5.3） |
| 重启 Kindle | **先退出看板**，回原生界面再长按电源键 |
| 插 USB 拷文件 | **先退出看板**（见 5.3），插线就稳了 |
| 看日志 | 插线后读 `F:\dashboard\dashboard.log` |

### 可调参数

| 参数 | 默认 | 作用 |
|---|---|---|
| `DASH_INTERVAL` | 600 | 刷新间隔（秒） |
| `DASH_FULL_EVERY` | 12 | 每几轮做一次整屏清白（压残影） |
| `DASH_CONTROL` | 1 | 是否查询服务端退出请求 |
| `DASH_WIFI_TOGGLE` | 0 | 是否只在拉图时开 WiFi（电池省电） |
| `DASH_WIFI_WAIT_MAX` | 30 | 等网络就绪的上限秒数 |
| `DASH_WIFI_RESTART_AFTER` | 3 | 连续几轮网络故障后 toggle 无线；0 = 关闭 |
| `DASH_FETCH_TIMEOUT` | 15 | 拉图的 HTTP 超时秒数 |

## 9. 如果重来一次

### 会提前想清楚的三件事

1. **接管屏幕 = 断掉所有按键交互。**
   任何"独占"式设计都必须**先设计好退出路径**，否则每次都能把自己锁在里面。
   （同理适用于 kiosk 模式、全屏应用、单用户模式。）

2. **深度休眠会改变设备对外的语义。**
   按键、USB、网络 —— 在 suspend 状态下行为都可能和运行时不同。
   **做电源管理之前，先把"睡/醒会造成什么副作用"列一遍。**

3. **静态图的"时间"是死的。**
   服务端渲染的图，离线时既不更新也没法自证"我过期了" ——
   **要么设备端叠加时间，要么接受"看不出数据新旧"。**

### 哪些做法是对的

- **渲染放服务端** —— 调试体验天差地别（浏览器秒级 vs 墨水屏秒刷）
- **先写探测脚本再写解析代码** —— 省掉了大量盲猜
- **失败方向选安全的那一侧** —— 网络抖动不会误退看板
- **配置落文件而不是环境变量** —— 从搜索框触发时根本没有 shell 可以 export
- **对比实验定位问题** —— 比在代码里推理快得多

### 哪些该早点做

- **早点跑探测脚本**（`eips -i`、`;log` 通道、按键能力位图）—— 这些都是"一次搞清楚，长期受益"
- **早点接受"取舍"而不是"修复"** —— 比如"长按弹菜单"和"深度休眠"就是不可兼得，早点认了能省很多时间
- **早点把日志做结构化** —— 日志里能区分"本机没网"和"服务端挂了"，排查会快一倍
